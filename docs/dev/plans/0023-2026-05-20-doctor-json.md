# Doctor JSON Inspection Surface

Date: 2026-05-20

## Scope

Add a machine-readable `codex-wake doctor --json` output mode for automation that needs to inspect wake runtime readiness without parsing text diagnostics.

## Non-Goals

- Do not change wake record schema version.
- Do not change service installation behavior.
- Do not make claims about active Codex hook loading beyond existing ack evidence.
- Do not add a separate health daemon or live polling API.

## Current State

Closed by [Doctor JSON Inspection Surface](../verification/0024-2026-05-20-doctor-json.md).

## Plan

- Add `doctor --json`.
- Factor doctor data collection into one structured summary used by both text and JSON output.
- Preserve existing text keys for operator continuity.
- Keep paths stringified in JSON.
- Include the existing hook ack evidence and trust note verbatim enough for automation to classify `unknown_without_ack` versus `observed_ack`.

## Acceptance Criteria

- `codex-wake doctor` preserves the existing text diagnostics.
- `codex-wake doctor --json` emits valid JSON.
- JSON includes repo root, wake root, command paths, tmux path, hook config status, hook runtime evidence, service status, service paths, and trust note.
- Tests cover both text compatibility and JSON shape.
- Installed CLI smoke verifies `doctor --json`.

## Definition Of Done

This lane can close when source tests and installed CLI smoke verify the JSON doctor output, and verification evidence is recorded.
