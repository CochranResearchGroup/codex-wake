## Outcome

Prove whether one synthetic message can reach an already-open, exactly identified Grok conversation through a native method or separately qualified terminal input. Return one selected feasible route or a bounded negative result that explains why implementation cannot yet meet the approved requirement.

## Scope

Observe installed runtime/session controls and build an isolated bounded probe. Record the receiver's pre-existing session ID, process generation, UI attachment, candidate method, acceptance evidence and resource envelope. Keep transcript content private and synthetic.

## Non-goals

Do not enroll production peers, send into existing user sessions, change authentication/configuration, bypass permissions, restart a shared leader or treat a resumed headless clone as the open TUI.

## Acceptance Evidence

- [ ] AC1: show the same pre-existing conversation receiving the synthetic prompt, with identity before and after.
- [ ] Separate native availability from successful live delivery; terminal observation is weaker than a receiver receipt.
- [ ] Demonstrate busy/unknown handling and a negative identity case without unintended input.
- [ ] Respect the spec's two-recipient/six-submission/five-minute envelope; retain uncertain outcomes without retry.
- [ ] Return the qualified route, limitations and reproducible sanitized receipt, or an explicit not-qualified verdict.

## Repository Surface and Risks

Runtime executable help, session controls and terminal host, with an isolated probe artifact; no production adapter changes.

Shared-backend session attachment, caller attestation and idle/queue controls may not be available. Live provider effects require the exact disposable-session scope before execution.

A complete slice requires its stated evidence. Source completion, integration,
installed acceptance and external publication remain separate states.
