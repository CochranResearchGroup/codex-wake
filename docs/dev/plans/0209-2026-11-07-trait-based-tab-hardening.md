## Problem Statement

The operator needs Codex Wake to understand and manage existing Byobu/tmux and Windows psmux tabs from WSL, PowerShell, API and MCP. Useful management includes discovering what each pane is running, distinguishing session presence from turn activity and TUI responsiveness, detecting current visible errors, and grouping or acting on those observations without losing work.

Existing source and scoped acceptance deliver important pieces: ordering and undo, exact-conversation lifecycle, cross-host adapters, modded Codex health and local prompt/response control. They do not establish a complete ordinary-user tab workflow. The deployed tabs list command currently fails without an explicit root, the canonical controller lacks workspace configuration, and the configured attachment factory omits the observation wiring needed for meaningful grouping. Existing parent plans and original ticket indexes also drift from later implementation and deployment evidence.

This specification hardens and completes those existing capabilities. It does not treat previously closed source tickets as production acceptance or replace their owners with a second controller.

Owner: ecochran76 / primary coordinator. Priority: P1. Specification state: READY; operator confirmed the acceptance seam on 2026-11-08. Implementation requires dependency-aware slices; source, integration, installation and operational qualification remain distinct.

## Solution

Provide one coherent tab/session management interface with automatic same-user discovery, rich independently qualified traits, named groups, saved filtered views, manual lifecycle and movement, and reversible organization. Complement the existing exact controlling-TUI health feature with activity and current visible-error observations. Support stock Codex, modded Codex, Grok Code and SSH classification now; disclose capability differences. Claude Code is future scope.

Observe through bounded background monitoring and explicit refresh. Saved views may update automatically. Physical rearrangement and automatic error responses are separate effects with explicit opt-in. Preserve manual placement, pins, focus, drafts, credentials, native history and exact conversation/account ownership.

Deliver a useful installed path first: no-root discovery → meaningful trait inspection → grouping preview → actual apply → conditional undo, from ordinary WSL and PowerShell callers with API/MCP equivalents. Then complete manual CRUD/movement/holding and exact workspace recovery, followed by optional automatic organization.

## Implementation Decisions

### One controller and independent observations

Reuse the existing host inventory, session discovery, managed identities, native health, terminal adapters, operation journal, permission/admission and lifecycle owners. No second scheduler, session registry, observation database or independent prompt-delivery path is introduced merely for tab organization.

A tab trait describes a terminal attachment or associated session. A tab group is a named or criteria-based collection; a tab view is a filtered/ordered presentation. Group membership and view refresh have no physical movement effect by themselves. Physical placement in a terminal session remains an explicit layout operation.

Observe panes individually. Tab summaries expose mixed constituents rather than assigning a misleading single account/harness/repository. Whole-tab layout operations preserve pane membership; mixed or insufficiently qualified windows remain protected unless a separately specified explicit supported operation applies.

The public observation model keeps at least these dimensions independent:

- Host, execution environment, workspace, tab and pane identity/generation.
- Harness and stock/modded build identity, supported account/profile identity, repository/worktree identity and SSH remote context where observed.
- Coding-session presence and conversation binding.
- Turn activity: running, idle, waiting-for-input, disconnected or unknown, with more detailed supported reasons retained.
- Exact controlling-TUI responsiveness, its deadline/freshness and unsupported/unknown outcomes.
- Current visible error presence and bounded message/location evidence, including explicit uncertainty.
- Observation provenance/time, freshness, capability and confidence/qualification information per dimension.

Do not infer a harness solely from a tab title, build identity solely from a version string, remote harness presence solely from SSH, or TUI health solely from process liveness. A responsive TUI can be idle, running or displaying an error. A working turn can be unresponsive. No single healthy bit replaces these facts.

### Trait observation and current visible errors

Prefer existing structured session/native evidence when available. Complement it with bounded terminal presentation observation for visible conditions that structured status does not expose. Red text alone is not sufficient evidence of an error. Distinguish a current bottom-of-screen error from historical scrollback, resolved/dismissed output and unsupported private presentation states. If uncertain, report suspected/unknown with provenance instead of inventing certainty.

Retain bounded error text, pane/screen location, observation time and supporting source while avoiding unrelated terminal transcript capture. Terminal content is data, never executable instructions to the controller. Keep diagnostic artifacts private and exclude credentials or unrelated private content from public receipts. Observation must not type, dismiss prompts, resume work, consume queued input or create provider turns. Report unsupported capture explicitly.

### Bounded refresh and useful defaults

Use automatic same-user discovery and existing initialized controller selection. Explicit selectors and roots retain precedence. Do not add manual per-session grant/enrollment preparation for ordinary owner inspection and supported control. This preserves host/user boundaries and externally imposed limits rather than weakening them.

Reuse event observations where available with bounded polling for other capabilities. Freeze documented default refresh/staleness intervals, per-probe deadlines, concurrency and output/retention caps in the implementing slice before installed qualification. Slow, offline or disconnected endpoints cannot block the complete inventory or trigger unbounded process trees. Expose manual refresh, monitoring status, stale data and diagnostic outcomes. Unknown is not absence and stale is not healthy.

### Groups, views and physical organization

Support repository ordering, named groups and placement into separate compatible terminal sessions. Saved views combine filters, sorting and layered grouping by supported traits, including remote host, harness/build, account/repository, session presence, activity, health and errors. Persist definitions and stable references; reevaluate membership from fresh observations without using changing tab indices as identity.

Preview reports exact source/destination identities, target positions, pinned exceptions and reasons. Apply rechecks current layout, bindings and input/focus state before effects. Record durable pending effects and verify each outcome. Conditional undo requires the recorded post-layout; it never overwrites later human changes. Distinguish already-arranged no-op from inability to qualify movable tabs.

Automatic view refresh is enabled independently of physical organization. Physical automatic arrangement is explicit opt-in, debounced and rate-limited, respects pins/manual placement, survives restart without repeating obsolete moves, and has an easy visible pause/disable control. This specification does not authorize automatic error remediation; future explicit response rules retain their own acceptance requirements.

### Unified lifecycle and movement

Expose typed create/list/show/rename/focus/reorder/move/park/restore/close operations using existing lifecycle owners and supported backend capabilities. Preserve compatibility aliases. Ordinary use needs meaningful arguments/help rather than hand-written operation envelopes; exact generations and durable request identity are resolved and retained internally. Advanced machine interfaces retain explicit pins.

Within a compatible terminal server, move whole live windows while preserving process/conversation identity, focus rules, wake/mailbox routing and cumulative resource accounting. Resolve source/destination/name collisions in preview; refuse ambiguous targets. Parking records original placement and restores without recreating agents. Closing an attachment preserves saved history; active/pending-work guards identify affected work and require the existing explicit force behavior when supported. Never substitute conversation deletion for tab closure.

Cross-backend movement is a supported conversation reattachment workflow, not live process transfer across operating systems. Preserve exact account, owning execution environment and conversation; verify the destination before retiring the source attachment. A destination psmux view may connect to an existing WSL-owned conversation where qualified; it does not receive copied credentials or imply a Windows-native conversation owner. If the runtime cannot support this continuity or simultaneous attachment verification, return explicit unsupported/held and preserve the source. Do not silently create a linked successor or substitute a new account.

### Recovery, parity and adjacent-feature hardening

Extend the existing exact-conversation inventory/resume and workspace recovery work. Capture bindings durably before outage; recovery previews missing, conflicting, unavailable and unsupported mappings. Restore eligible saved conversations to intended attachments without arbitrary command replay, per-agent enrollment rituals or duplicate clients. Preserve non-coding tabs, native history and existing budgets. Reconcile uncertain prior recovery before any retry.

CLI, API and MCP use the same operation semantics with a declared capable/local-only/unsupported matrix. WSL and actual PowerShell clients talk to the same WSL execution authority. psmux uses the qualified Windows presentation bridge; a bridge protocol fixture alone is not native Windows acceptance. Stock/modded Codex and Grok Code report truthful per-harness capabilities; arbitrary Grok TUI ownership and exact health must not be claimed from headless ACP evidence.

Include regression acceptance for local prompt acknowledgement, output modes, native slash actions, own-session limits, caller disconnect/result retrieval and codex-bots identity/health/results. Reuse existing flow, governor, account and recovery specifications; update their remaining-acceptance maps rather than redesigning them inside this feature. The first milestone is useful installed discovery and grouping/undo; lifecycle, manual movement and workspace recovery follow; optional physical automation follows dependable manual controls.

## Testing Decisions

The primary acceptance seam is the installed Wake public operation service exercised through its normal CLI, API and MCP clients from WSL and actual PowerShell, against disposable real Byobu/tmux and Windows psmux workspaces. Validate visible outcomes plus exact conversation/attachment identity. This seam catches bootstrap, root selection, factory observation wiring, presentation adapters and client parity that isolated helpers miss. The operator confirmed this acceptance seam on 2026-11-08.

Use existing public lifecycle/organization, local session-control, exact TUI health, cross-host psmux, prompt-result and workspace-recovery harnesses. Focused public-operation tests drive regressions red before green; injected runtime evidence proves only the modeled contract. Native TUI, actual Windows presentation and provider behavior retain separate acceptance receipts. Avoid tests coupled to private helpers or counts of implementation calls.

Required acceptance groups:

1. Ordinary-shell no-root discovery from repository and unrelated directories, explicit-root precedence, useful missing-config and offline outcomes, no tracebacks, and same-user operation without hand-written per-tab grants.
2. Stock/modded identity, Grok Code capability declarations, SSH/local/remote context and mixed-pane inventory. Unsupported or stale remote observations remain explicit.
3. Session present/absent independently of running/idle/waiting, healthy-loop versus process-alive-but-stalled negatives, fresh/stale/offline observations and bounded monitoring cost.
4. Current visible bottom error, ordinary red text, historical scrollback, resolved error, structured/terminal disagreement and unsupported/private capture. Draft/input/queue/history preserved; zero model prompts for observation.
5. Layered filters/groups/saved views, repository/worktree grouping, pins/focus/mixed/unknown protection, actual reordered layout, conditional undo and a separately diagnosed no-op.
6. Create, rename, focus, compatible whole-window moves, parked/restored placement, name/placement conflicts and guarded close, with exact bindings and pending wake/mailbox routes preserved.
7. Cross-backend exact-conversation destination verification before source retirement; unsupported continuity and uncertain failure preserve source. Same intent never duplicates attachments or work.
8. Workspace recovery from captured durable bindings after restart/layout restoration, repeat recovery, missing history/account/build and non-coding tab preservation. Any disruptive acceptance uses disposable state, not operator sessions.
9. CLI/API/MCP outcome/error parity and actual PowerShell to WSL/Windows psmux journeys. Installed help/reference/completion match supported operations and disclose exceptions; completion remains local/read-only and bounded.
10. Existing codex-bots prompt/health/result workflow, response modes, slash interactions, voluntary self-limits and reconnect/cancellation/uncertain delivery retain their original contracts. Flows and governor controls receive affected regressions where shared owners change.
11. Opted-in physical organization preserves manual overrides/pins, debounces state changes, pauses visibly, disables without new effects, and resumes after restart without replaying obsolete movement. Error detection alone performs no remediation.

Every implementing ticket names its bounded behavior, existing public seam, dependencies, source commit, immutable installed prefix/builds, commands, duration, failures and acceptance boundaries. Run applicable local checks on supported Python versions instead of paid hosted GitHub CI; distinguish focused, presubmit, comprehensive and live acceptance. Preserve failed/uncertain receipts. Provider turns, forced reboot, production tab changes and native daemon replacement require separately authorized bounded packets; specification publication does not perform them.

## Out of Scope

- Claude Code and additional runtime adapters for this milestone.
- A Windows-native Wake execution server/service, public OAuth ingress rollout or new cross-user/tenant authority model.
- Transferring live OS processes between WSL, Windows, machines or incompatible terminal servers.
- Silent account substitution, credential copying, conversation deletion, automatic successor creation or budget renewal during tab movement/recovery.
- Automatic error retry/dismissal/interruption/restart merely because an error was detected.
- Replacing the existing session inventory, operation journal, health owner, flow engine or governor with parallel machinery.
- Universal semantic understanding of arbitrary terminal applications or unsupported Grok TUI control.
- Declaring every historical open parent completed, reopening every closed child, or treating this spec as implementation/deployment authority.
