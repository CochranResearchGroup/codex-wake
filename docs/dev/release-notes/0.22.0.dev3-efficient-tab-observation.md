# Codex Wake 0.22.0.dev3 candidate — efficient tab observation

Status: development candidate; resource qualification and review remain open.
Plan0216 / specification#540 / tickets#541–#547 govern delivery. This branch
does not install or enable production monitoring.

## Changes

The existing host monitor retains metadata feeds and identity-qualified caches.
Native activity updates, exact responsiveness and redacted visible errors have
independent controls and schedules. Quiet connected turns remain active; source
loss removes uncertain cues while preserving palette, names and static type.
Formatting consumes shared revisions and updates changed windows, with original
rollback baselines retained. Native read-only formatting channel qualification is
the remaining measured CPU repair before installed acceptance.

Use the existing `tabs monitor-start`, `monitor-status` and `monitor-stop` commands.
Boolean health/error/activity flags and intervals are shared by CLI, API andMCP.
See [tab observation](../../agents/tab-observation.md) and
[tab formatting](../../agents/tab-formatting.md) for controls and limitations.

## Compatibility and qualification

Python3.11+ remains supported. The package now requires msgspec0.22 for faster
JSON reads, with a stdlib fallback preserving legacy values and error behavior.
Existing strict encoders, digests and saved-state schemas stay unchanged. Install
through the package dependency resolver; copying source without dependencies is
not a qualified installation.

Stocktmux/Byobu andCodex binaries remain unchanged. Existing unsupported native
event paths retain explicit fallback/unknown states. No new Windows service or
external OAuth exposure is introduced.

Acceptance requires the exact immutable installed package:100tabs,60seconds each
idle<=1% andactive<=5% ofonecore, aggregateRSS<=256MiB, p95eventlatency<=2seconds,
actual CLI/stdio/authenticatedAPI/MCP, read-only existing-host proof andcleanup.
Failed receipts remain in docs/dev/evidence/plan0216/qualification547. Final
qualification and the single Standards/Spec review will be linked here at closure.
