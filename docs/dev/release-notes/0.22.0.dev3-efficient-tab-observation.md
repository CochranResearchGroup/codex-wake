# Codex Wake 0.22.0.dev3 — efficient tab observation

Development candidate for Plan 0216 / specification #540 / tickets #541–#547.
Delivery is a validated branch and draft PR; production installation and monitor
activation require a separate operator instruction.

## Changes

The existing host monitor retains metadata feeds and identity-qualified caches.
Native activity, exact responsiveness and redacted visible errors have independent
controls and schedules. Quiet connected turns remain active; source loss removes
uncertain cues while preserving palette, names and static type. Formatting updates
changed windows and preserves original rollback baselines. A bounded read-only
formatting client avoids repeated native reader launches. Revision-qualified JSON
rows avoid serializing unrelated tabs on every activity update.

Use `tabs monitor-start`, `monitor-status` and `monitor-stop`. Activity, health and
error flags and intervals are shared by CLI, API and MCP. See [tab observation](../../agents/tab-observation.md)
and [tab formatting](../../agents/tab-formatting.md) for controls and limitations.

## Compatibility

Python 3.11+ remains supported. The package requires msgspec 0.22 for faster JSON
reads, with a standard-library fallback preserving legacy values and errors.
Strict encoders, digests and persisted schemas remain unchanged. Install through
the dependency resolver; copying source without dependencies is unqualified.

Stock tmux/Byobu and Codex binaries remain unchanged. Unsupported event paths
retain explicit fallback/unknown states. No Windows service or new external OAuth
exposure is introduced. Source matching now preserves exact endpoint, full home,
peer birth and epoch; skipped reconciliation cannot renew dynamic evidence.
