# 0.13.1 — Retained native scheduling intent

Native scheduling no longer drops a follow-up when trusted time acquisition is
unavailable. Schema6 retains and deduplicates the exact request, exposes pending
recovery/availability alerts and lets a compatible worker recover it on its poll
interval. Stable keys identify automated successors across retries and terminal
states; changed requests conflict.

Authenticated host elapsed evidence can qualify relative delays while strict
UTC is unavailable. Absolute UTC deadlines/stops still require qualified UTC;
per-request precision does not relax StableTime's below100ms service contract.
Counter epoch changes hold unknown origins. Initially unanchored relative
requests remain retained and alerted; recovery cannot restart their original
delay or extend their expiry.

Upgrade the CLI and worker together. Readers through0.13.0 hold schema6; rollback
preserves those records for a compatible worker. Other record families retain
their existing source semantics. Activation must first reconcile the separate
uncommitted StableTime adapter rollout, which this feature does not publish.
No release authorizes replay of failed monitoring events.
