# Wake0.11.1 acknowledgment and ordinary tab-close repairs

Live-tab and saved-conversation notifications now describe the required work
claim before processing and terminal acknowledgment. Both use the worker's
installed CLI, stop when an existing claim is returned, and retain existing
permissions, untrusted-peer and explicit reply-reopening rules. Result consumers
report and complete the result without generating another reply.

Ordinary tab-close inspection now distinguishes pending notification delivery
from receipt publication. A scheduler receipt is not a conversation identity and
does not itself require a tab to remain open. Pending/uncertain notifications,
nonterminal messages, pending wakes and damaged actual attribution still hold.
No state migration, receipt deletion, force-by-default or Codex patch is involved.
Rollback to0.11.0 restores the prior instructions and conservative false holds.
