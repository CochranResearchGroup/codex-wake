# StableTime retained-intent candidate (0.13.0 development)

This source candidate adds schema6 for native requests accepted while configured
StableTime supplies no finite supported UTC interval. Monitor recovery promotes
the same intent to schema5 once finite evidence returns. It never uses the guest
clock to establish UTC deadlines or expiry.

Configured StableTime intents persist their provider authority through admission,
later monitor evaluation and direct dispatch, even when the configuration selector
is subsequently disabled. Finite evidence from legacy NTP or Windows holds the
intent rather than substituting another provider. Malformed schema6 event history
is classified as held before promotion can touch it.

Relative delays without a supported creation origin start in full at the first
finite upper-bound admission. Absolute deadlines and their TTL remain fixed.
Overlapping identical active registrations are deduplicated. Unconfigured
legacy creation and existing versions1–5 remain compatible.

Schema6 is a deliberate incompatible predicate representation for older readers:
versions1–5 must hold it. Rollback must preserve schema6 files and their intent
history, then restore a capable reader to resume recovery. Do not rewrite them
as guest-timed records, retry native submissions, or infer queue nonacceptance
from missing observation. This document describes source behavior, not installed
runtime acceptance or a new released package version.

Focused validation uses public CLI creation, persistence across Python process
boundaries, monitor recovery, native submission interception, cancellation,
fixed expiry and concurrent overlapping retries in
`tests/test_pending_time_intent.py`. These tests inject time and native transport
at system boundaries; they make no live provider or queue requests.
