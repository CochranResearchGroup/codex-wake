# 0.8.0 candidate: opt-in network deadline authority

This feature branch adds network-first deadline wakes and a versioned mailbox migration. It is an isolated candidate, not a production installation or activation receipt.

## Commands and trust

`codex-wake time inspect` reports acquisition, admission and exclusions without opening a wake/mailbox root. `--offline` displays policy without host interop. Five operators are visible: Cloudflare, NIST and Alastyr are admitted under explicit unauthenticated plain NTP; Netnod and PTB remain disabled until their leap-scale profiles are qualified. Two agreeing independent operators are required; three admitted operators permit quorum after a single outage. Tied groups remain uncertain; healthy Windows UTC can fall back only when consistent with remaining usable network evidence. Running W32Time alone is insufficient. The current workstation's stopped service supplies no UTC fallback. Chrony NTS qualification timed out; authenticated UTC is not claimed. Netnod/PTB qualification and NTS remain explicit follow-up limits. The third source admission and live activation work are recorded in Plan0122 revision2.

On WSL, Windows QPC owns elapsed time and cached sample age. The collector does not adjust either clock or start services. Bounds describe collector completion. Creation uses that acquisition instant; evaluation uses the conservative lower bound. Host reboot invalidates elapsed observations, guest restart invalidates cached evidence while retaining the host rate guard. Unknown interop, stale evidence and incompatible clocks hold effects.

Options must precede the positional duration/timestamp because the remaining arguments are the resume prompt:

```
codex-wake after --network-time --app-server-thread-id THREAD_ID 10m -- Resume the task
codex-wake at --network-time --app-server-thread-id THREAD_ID 2027-01-15T08:01:00.123456Z -- Resume the task
```

These commands explicitly accept the displayed plain-NTP trust policy. A new network wake is schema 3. Relative deadlines use the accepted upper bound rounded upward to the record's whole-second creation precision. Explicit absolute deadlines retain fractional seconds. No trusted acquisition returns a retryable `time_uncertain` error without a new wake; retain and retry the original intent. Pending wakes retain their original deadlines across outages. Direct dispatch independently checks the network deadline gate. Cancellation does not require UTC and records an unknown timestamp explicitly. Archive requires accepted time; retention deletion uses accepted lower bounds, never guest wall time for schema 3.

## Compatibility and migration

Existing schema-1 wakes and schema-2 signal wakes keep their current behavior. The default writer remains schema 1. Only updated readers/daemons are qualified for schema 3; older unmanaged processes must be stopped before creating these records in their roots. Current readers hold unknown versions. This release does not remotely upgrade, fence or certify arbitrary historical binaries. A separate root is recommended for candidate evaluation.

Mailbox schema 2 also remains the default. The operator opts into schema 3 using:

```
codex-wake a2a network-time --bus-root ROOT --operator-capability FILE --accept-unauthenticated-ntp
```

Activation requires network consensus, quiescence, operator capability and no recovery hold. An existing legacy clock checkpoint must pass its original continuity guard and agree with network evidence. Activation cannot clear an existing anomaly. Existing envelope deadlines and the prior checkpoint are retained; schema change, policy, initial network checkpoint and migration receipt commit atomically. Schema-2-only clients reject the new mailbox schema. See [state contract](../evidence/plan0125/state-contract.md).

Before eventual production migration, stop writers/dispatchers, create and verify a pre-migration backup, inspect current time and guard state, migrate, verify original message deadlines and reader identity, then resume only under separately authorized rollout. Backups report and verify the actual mailbox schema. There is no in-place downgrade or checkpoint deletion command. Rollback requires a verified pre-migration snapshot and the existing no-loss/recovery-gap rules. New writes after migration must be reconciled; restoring an old snapshot does not preserve them. For a disposable candidate, remove the disposable root and reinstall the prior wheel; preserve any evidence first. Do not expose schema-3 records to old daemons as a rollback procedure.

## Qualification boundary

The installed acceptance harness uses an isolated virtual environment, temporary wake/mailbox roots and `--no-dispatch`. It verifies real network acquisition, fresh-process persistence, due evaluation, inspectable prompt and cancellation. Fault fixtures separately cover outages, uncertainty boundaries, Windows health, ties, boot identities, sleep-length advancement, interrupted commits and concurrency. Controlled boot/sleep inputs are not actual host reboot/suspend evidence. No real session resume transport, production store migration, production package upgrade, service control or clock adjustment was performed.
