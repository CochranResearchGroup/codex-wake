# Codex Wake0.15.1 — Native client startup readiness

Fixes a startup race in0.15.0: an observed Codex process can appear before its
native thread/title metadata binds to the pane. Keep that exact recorded pane
in `starting` until its expected identity resolves; a different known thread
still returns `target_changed`. No relaunch, fallback or message admission is
permitted by an unbound process. Repeated intents retain the original thread.

The owned0.15.0 post-install proof exposed this race and cleaned up without model
turns or residue. The active command/skill installation was restored to0.14.0
while the patch was qualified. Original release/evidence remain for provenance.
This patch includes0.15.0 MCP informal-tab targeting and explicit startup policies.
