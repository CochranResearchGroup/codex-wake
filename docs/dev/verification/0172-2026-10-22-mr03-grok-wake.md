## Implemented source

Schema7/runtime-envelope1 adds a distinct Grok target and durable scheduling
intent. It shares the existing schema6 clock eligibility and validates its own
runtime target; old formats and Codex actor namespaces retain their meaning.
An original stable key, root, binding digest, trigger, TTL and clock anchors are
retained across acquisition outages and retries. No new delay is manufactured.
Older readers hold schema7. Managed-reader advertisements include7.

An operator binds a managed-launch, already-open Grok1.0.40/eb1a2256660d minimal
TUI through `grok bind --allow-terminal-input`. The binding pins the user-owned
private tmux socket, exact pane PID, boot/start generation, executable digest and
launch session argument. Registration freezes its file digest. Changed scope,
unknown versions/methods/policies, missing processes, drafts, dialogs and unknown
composers refuse delivery. An observed missing/initializing session is not ready.

Grok-specific process access, UI recognition and terminal input stay in the
adapter/host. The scheduler owns trusted-clock and cancellation admission,
root/wake and user-scoped pane locks, original expiry, durable submission UUID,
prompt hash and uncertainty before input. A late handoff window is refused;
there is no fallback to another recipient or to Grok native control.

Submission refreshes the local `/session-info` control and checks the exact
session/composer again before a literal bracketed paste. A standalone original
submission-marker line can establish terminal observation, with private-frame
and marker hashes. A composer draft cannot. Terminal observation does not
establish execution, work claim, receiver acknowledgment or an A2A reply.
Ambiguity persists without replay. Direct human keystrokes are not atomic with
Wake's checks, and no exactly-once guarantee is claimed.

`grok after|at|file` and `grok show|sessions` expose the new route. MCP offers
host-root-scoped scheduling/discovery/evidence tools, never enrollment, socket
selection or executable selection. Registration requires a compatible active
monitor in the agent-facing route. If missing, it returns a structured held
receipt identifying the retained original intent; reusing its key does not
rebase or duplicate it. This is not sender attestation or cross-runtime A2A.

[Persisted schema contract](../wake-record-schema.md) records compatibility.
This packet does not install a production release or change a service or grant.
