## Change and ownership

The existing Codex native wake path now uses `RuntimeAdapter.resolve`, `observe`,
`submit` and `reconcile`. `CodexRuntimeAdapter` owns thread reads, optional exact
saved-thread resume, the queue command and safe diagnostics, and bounded exact
queue/turn evidence lookup. It is a substantive runtime boundary, not a registry
of speculative providers. The default public dispatcher and schema6 intent
caller use it; tests may inject a runtime at the public dispatcher.

The core retains locks, cancellation and trusted-time gates, expiry, original
prompt identity, durable uncertainty before the effect, attempt count and no
resend during reconciliation. Existing record formats, CLI/MCP contracts and
other transports retain their meaning. An additive observation projection
reports readiness and capabilities without opaque binding details.

[Version1 compatibility and evidence contract](../plans/0172-multi-runtime/runtime-delivery-contract.md).
No durable Grok target, plugin SDK, release, production installation, service
change or provider conversation is part of this ticket. Native acceptance is
not an authenticated receiver acknowledgment.
