## Public contract

`controller auth-configure --issuer ORIGIN --resource RESOURCE --owner SUBJECT` creates a private local authority under the selected Wake root, plus a private operator consent file. It does not start a listener. Issuer must be an exact canonical HTTPS origin (no path/trailing slash); resource is one exact HTTPS identifier shared by API/MCP. Loopback HTTP is allowed for disposable acceptance. No provider credential participates. `controller serve --port PORT` binds loopback only. External TLS ingress/production deployment is a separate gate.

Discovery: `GET /.well-known/oauth-authorization-server` and `GET /.well-known/oauth-protected-resource`. Public-client registration: `POST /register`. Browser authorization: `GET /authorize`, then explicit operator consent `POST /authorize`, requiring the private consent secret. The page shows the full requested client, resource, scopes and targets. Codes are one-use, expire after 120 seconds and require exact redirect URI/resource plus S256 PKCE. Authorization-code and rotating-refresh exchanges use `POST /token`; refresh replay revokes that grant. Access credentials expire after 600 seconds; refresh credentials after 86400 seconds. Opaque credentials are stored only as SHA256 digests in private SQLite storage bound to the exact issuer/resource. Client registration does not establish a principal or authority.

`controller authorize-client` is a local operator approval alternative for explicitly named owner/service principals. `controller revoke-grant GRANT` independently revokes one grant. OAuth `POST /revoke` supports public-client token revocation. All returned actors identify subject, principal kind, client, grant, issuer/resource and scopes. There is no delegated token exchange.

`POST /operations` takes `{operation, arguments}`. `POST /mcp` implements authenticated stateless JSON MCP initialize/notification, ping, tools/list and tools/call. Successful read operation envelopes are equal across direct API, OAuth MCP and `controller remote --endpoint ORIGIN --token-file PRIVATE_FILE OPERATION`. CLI refuses non-private bearer files and does not follow redirects with credentials. No transport session grants cached authority: every request and completed observation revalidates its current grant. GET MCP streaming is explicitly unsupported (405 for an authenticated caller).

Capabilities separate `observe`, `control`, `recovery`, `admin`, `account.observe` and `configuration.observe`. Inventory list filters every row by target grants; resolve checks the resolved target, including stale-generation rejection from the existing owner. Account/config capabilities never follow from inventory observation. Account grants must specify the full exact host/environment/provider/account/home/home_generation/configuration_revision target. Configuration data comes only from the account owner and its redaction. The list collection is filtered before serialization; singleton account/config reads require target authorization before serialization. Optional account service is loaded only from host-configured `wake_root/controller-accounts.toml`; no client can choose paths or host identity. Account MCP tools are hidden when that owner is absent. The common policy table is the explicit extension point for the ticket395 operations.

Input/control, recovery and remote administration operations are intentionally unsupported in this read-only increment. Revocation therefore reports `no_owned_active_work` and no uncertain effects; it does not cancel unrelated grants or invent cancellation of non-owned provider work. A restarted listener reuses the private authority but authenticates each request again. Rotation invalidates old credentials; reconnect neither creates operations nor renews allowances. No durable mutating operation/rebinding claim is made.

Listener bounds: loopback, 16 concurrent connection handlers, five-second socket I/O deadline and 65536-byte request body maximum. Credential-bearing HTTP requests are never logged. Origin checks and explicit rejection of untrusted principal headers protect the edge; verified bearer actors are the only remote identity source. MCP is stateless JSON transport; WebSocket/SSE streaming and production ingress are outside this ticket.
