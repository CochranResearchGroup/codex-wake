## Contract and owner boundary

`HostRegistry(path, now=...)` owns explicit host/environment registration, observation timestamps and SSH-principal mappings in private SQLite storage. `HostOperations(registry, transport=..., local_operator=False).execute(operation, arguments, actor=None, authorize=None)` owns route admission and durable transport receipts, while the selected host-local `ControllerOperations` remains execution authority. The registry path is fixed by `host_commands.owner(root)` to `root/controller-hosts/registry.sqlite`; it is never selected by remote request arguments.

A target is exactly `{host, environment, authority, generation}`. One host may contain distinct Windows and WSL environments, each with its own authority. Registration creates a stable random generation; a source registry can explicitly import the exact generation exported by the destination. Re-registering an identical record returns the existing identity without renewing freshness. Changing authority, generation, transport configuration or capability under an existing host/environment is rejected as `authority_conflict`, preserving existing evidence rather than silently retargeting. Destination replacement therefore requires explicit new registration identity, not a selector rewrite.

`hosts.list` returns `{environments:[...]}` and retains offline/stale rows. `hosts.resolve` returns `{environment:...}` and optionally checks `expected_target`. Freshness is a timestamped observation with a thirty-second interval, independent of stored online state. New route admission requires both current and online observation. `observe` is an explicit local operator act; connecting, reconnecting and retrying never renew it.

`hosts.route` accepts exactly `{target, operation, arguments, operation_id, idempotency_key}`. The trusted actor must have the operation capability and a grant including the full exact host/environment/authority/generation. Missing actor fails closed unless the factory explicitly opts into local operator CLI authority. Namespace/account constraints are preserved as attenuation of the fixed destination principal; clients cannot provide subject, client identity, arbitrary remote command or a new principal. `authorize` may reauthenticate immediately before transport submission. Changed/revoked/expired admission becomes `not_started/not_submitted`, and remains bound to the original idempotency key.

Only existing read operations are routable: inventory.list/resolve, accounts.list/resolve and configuration.explain. Capabilities remain observe, account.observe and configuration.observe respectively. Unsupported mutation/control/recovery registration and routes fail before transport; there is no offline mutation queue, automatic retry, provider work or invented cancellation result. Production mutation recovery remains a later service boundary.

The SSH transport executes a fixed operator-registered executable/destination/remote command with `-T -oBatchMode=yes -oConnectTimeout=5 -oStrictHostKeyChecking=yes -- DESTINATION COMMAND`. The default executable is `ssh`; test fixtures explicitly replace it with a labeled synthetic executable. The transport has a ten-second deadline, 65536-byte request/response frame bounds and bounded full-duplex I/O. No credential is placed in argv, requests, logs or receipts. SSH authentication/key provisioning and forced-command installation are external deployment responsibilities; this slice changes no sshd configuration.

The receiver is a fixed sshd/authorized_keys forced command, e.g. installed `codex-wake hosts ssh-serve --principal-id FIXED --target PINNED_JSON` with the host Wake root fixed by deployment. Principal ID and target must be outside client-controlled request JSON. A receiver looks up that explicit mapping, requires finite unrevoked grants, verifies its host/environment/authority generation, intersects caller attenuation with mapped scopes/targets, then runs the existing ticket399 `ProtectedOperations` over the host-local operation owner. SSH connectivity grants no owner/admin privilege. Caller scope JSON can only narrow the fixed mapping. Provider and native credentials never transit this channel. Account/config reads reuse their existing owner/redaction.

A route receipt separates submission, execution, delivery, acceptance and effect. Durable admission precedes transport. Duplicate keys return the original receipt; changed inputs conflict, and operation IDs cannot be rebound to a different key. An interrupted admission or response loss remains unknown/uncertain with `effect=none_read_only`; the receipt does not assert that a lost read completed. Restart/reconnect never resubmits it. Known pre-submission failure is not_started/not_submitted; a valid authority rejection is execution=failed with the original typed result. The delivery journal is a transport receipt, not a second native/provider execution store or authority.

## Public adapters

`host_commands.register_parser(subparsers)` and `command(args, root=None)` expose top-level `hosts list/resolve/register/observe/map-principal/revoke-principal/route/ssh-serve`. Administrative commands are local operator configuration, not remotely admitted operations. The module also exposes installed `python -m codex_wake.host_commands --wake-root ROOT hosts ...`, permitting disposable package acceptance before primary-owned shared registration. Common service registration uses the same `HostOperations` result shapes; OAuth remote route integration must inject the verified Actor and current-auth callback. The primary owns API/MCP/combined CLI parity receipts.
