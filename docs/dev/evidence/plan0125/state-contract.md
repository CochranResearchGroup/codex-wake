# Network mailbox state and migration contract

Schema 2 remains the default legacy mailbox and retains its original clock anomaly guard. Network time is an explicit operator migration to schema 3, not a constructor flag that bypasses an existing checkpoint. Older schema-2-only clients reject schema 3. Current readers validate both schema and the exact versioned time policy before use.

Activation requires accepted network consensus, operator authority, no recovery hold, and no live lease or unresolved dispatch attempt. If a legacy clock checkpoint exists, its original continuity guard must pass and its time must overlap network bounds within the legacy one-second allowance. An anomalous/disagreeing checkpoint cannot be reset by activation. The pre-migration checkpoint is preserved with an operator migration receipt; immutable envelope deadlines are never rewritten.

Schema 3 permits a NULL receipt timestamp for time-independent cancellation or audited operator inspection when UTC is unavailable. Details state that UTC was not observed. Such cancellation suppresses pending notification but creates no new receipt-signal dispatch while time is uncertain. Metadata inspection and cancellation cannot fabricate a successful recipient consumption/transport receipt. Existing transport-uncertain and too-late cancellation guards remain intact.

Relative TTL admission without bounded time returns `time_uncertain`; callers retain their idempotency key and retry the original intent. With bounded time, TTL is anchored at the accepted acquisition instant's upper bound, not a guessed guest timestamp. This is the defined creation instant for relative mailbox intents. Original deadlines survive retries, outage, sleep and process restart. Expiration requires the lower bound to reach the deadline; delivery is held if the deadline lies inside the interval. Metadata inspection intentionally does not evaluate expiration or change time anchors. The schema-3 public time provider is a trusted acquisition seam, not an API for accepting user-supplied clock claims.

Network roots automatically select network acquisition; a missing/unhealthy provider cannot silently revert to Linux wall time. Windowed UTC remains operationally trusted, explicitly unauthenticated plain NTP under this opt-in policy. The receipt records that choice; the implementation does not claim hostile-network authenticity.

Before any eventual live migration: pause/quiesce, create and verify a same-root backup, qualify the legacy guard against current network bounds, migrate atomically, then verify the installed candidate and original deadlines. No live store is touched in this goal. Schema-3 backups must report and verify actual schema 3. Rollback uses a separately authorized, verified pre-migration snapshot with the existing no-loss/recovery-gap rules; no in-place schema downgrade or checkpoint deletion is offered. Post-migration accepted writes forbid pretending an old snapshot is current. Candidate release instructions must preserve this gate.
