# Goal-limit UX development candidate

The source candidate is0.22.0.dev0, not a general release. Its exact commit and
installed package-file hashes own qualification. Existing production0.21.2 and
masked service remain unchanged. No release or default activation is claimed.

The new receipt fields enrollment_revision, poll_ack, notice_ids, budget_history,
lifetime_tokens_before_window and renewal_pending extend persisted authority.
Run a compatible controller and enrollment/renewal writers together. Older
controllers do not implement the pending-renewal fence and must not supervise an
in-progress new renewal transaction. Preserve original ledgers/history; use the
qualified graceful handover path for any separately authorized future activation.

Ordinary stock native runtimes lacking no-turn notice append/read cannot satisfy
conversation visibility; Wake retains unsupported delivery honestly. The experimental
native extension requires its exact pinned source/build manifest and qualified
response-level accounting writer, plus host-provided MCP caller metadata. Display
token totals cannot replace raw response evidence. Unknown descendant lineage or
unqualified response/compaction accounting holds; no counters are synthesized.

The stock0.164 frontend can render the existing message event from the extension.
The experimental native server remains a development build and is not declared
release-qualified or a replacement for the shared daemon. Final real watcher,
frontend and operator renewal receipts are recorded separately from source tests.
