# Scoped controller recovery (#404)

The policy owner separates read-only exact-loop observations from explicit recovery actions. Configuration creates an immutable policy in `observe` mode without scheduled enrollment. Its declaration pins exact target, evidence threshold, action sequence, interval, probe deadline, cooldown and cumulative attempt ceiling. Unsupported actions, including shared native restart, are refused. Supported actions are operator notification, original owned-operation cancellation under its existing authority, and exact-thread MCP refresh through the existing `scoped_refresh.poll_one` owner and private host profile. A refresh never replaces a client or changes a native goal.

`recovery list|show|configure|enable|disable|check|tick|apply|reconcile --arguments JSON` shares one schema/admission contract across CLI/API/OAuth MCP/native MCP/remote CLI. `check` observes only and never appends a notice. Repeated unknown yields persistent `suspected_unresponsive`, not restart authority. Explicit enable must retain its native activation notice before becoming automatic. Unknown or unsupported activation delivery holds the policy; reconciliation reads the original event instead of appending it again.

The already-running controller server schedules explicitly enabled policies through its bounded maintenance worker, without service installation or governor enrollment. Each pass selects at most eight policies using a fair retained cursor and stable occurrence intents. It coalesces missed checks rather than replaying a backlog. The trusted resolver revalidates the original OAuth grant or host-local grant before every step. Original scopes, targets, principal kind, identity and access-expiry are private immutable authorization metadata; public policy projections omit that snapshot. Token rotation does not renew it. Revocation/expiry/clock loss produces visible held status without issuing credentials, grants, resources or notices under lost authority.

Scheduling, freshness, cooldown and original authorization expiry use persisted `CLOCK_BOOTTIME` plus boot ID. Wall timestamps are presentation metadata. Rollback cannot reset deadlines or extend authorization; boot/elapsed discontinuity holds the original clock. Existing candidate policies without the required clock metadata remain held, not silently initialized with fresh deadlines.

One-command scoped disable changes mode/generation before reading original in-flight effects or delivering its deactivation notice. Every later native step checks the current generation. It preserves counts, deadlines, original uncertainty and accounting; no allocation API is called. Authorized scheduled observations continue after disable. Ambiguous actions or exhausted ceilings enter explicit `held` mode, preventing repeated interventions and notice spam while retaining observation. Reconciliation observes original cancellation/refresh/notice handles; it never replays an uncertain action or continues unsubmitted ladder steps implicitly.

The private policy journal is `controller-recovery/policies.sqlite` (schema1). Existing operation journal admission precedes actions. Exact-thread refresh receipts are private original-owner records under `controller-recovery/refresh/`. Host profiles are private `controller-recovery.json` version1 entries with `{target, refresh}`; the target and existing health endpoint must match exactly, native peer/home/image are verified, mode must be `thread_mcp_idle`, and1..32 MCP/catalog resource checks are required. Public `list/show` expose bounded scheduler heartbeat/status. A missing heartbeat is `not_running`; malformed, nonprivate, stale or clock-uncertain heartbeat is `unknown`.
