## Problem Statement

An operator's `/goal` resource limits must constrain executing work even when the agent ignores reminders, blocks inside a tool, or loses its observer. Existing objective accounting, lifecycle transitions and emergency controls provide foundations, but do not prove independent containment of all owned execution. Research intake #270 remains separate from this implementation specification.

## Solution

Provide opt-in strict execution containment for dedicated objective executors on qualified Linux/WSL systemd/cgroup hosts. Apply memory, swap, CPU rate, task and elapsed-time limits independently of the model. Couple the existing cumulative objective ledger to sampled token stops and an independent accounting-freshness lease. Expose actual coverage, exclusions, observations and verified stop outcomes through public lifecycle readback. Unsupported guarantees refuse admission.

## Implementation Decisions

- Confirmed by the operator: dedicated strict execution boundaries with explicit shared-service exclusions; objective-wide sampled token accounting including cached input and all attempts; stop on accounting loss and explicit renewal after exhaustion.
- Reuse ObjectiveLedger, resident lifecycle supervision and released emergency controls. Current main0a5c8d1 includes the v0.16.0 emergency-control integration; the research's earlier0.15.1 parity evidence remains historical, not current implementation acceptance.
- Add a host adapter behind existing public lifecycle operations. Bind objective/actor and exact native assignment to durable unit invocation and cgroup identity. Preserve intent-before-effect and uncertain-effect reconciliation. Do not create a second handoff framework.
- Strict coverage includes actual execution and attributable objective-specific service children. Shared services and external provider execution are excluded; reject a strict operation if its requested coverage cannot be provided. Same-user IPC escape is outside the demonstrated ownership model; do not advertise an adversarial security sandbox.
- Limits must be explicitly configured: memory, swap, CPU rate, tasks, session/objective tokens and time, polling interval, accounting maximum age, and checkpoint/termination grace. Validate combinations before admission. Experimental numeric caps are not defaults. Expose effective configuration and coverage.
- Retain original objective identity, absolute deadline, cumulative spend and reservations across refresh, handoff, concurrent work and restart. Aggregate objective controls must cover concurrent actors, with session controls no greater than their authorized share.
- Independent deadline and freshness-lease enforcement must not depend on the model or a successful native interrupt RPC. Fresh observations alone may renew the lease; they cannot move the objective deadline. A locally recent read of an unchanged stale usage counter is not necessarily fresh accounting; define observation versus consumption evidence explicitly.
- Token stops use the existing cumulative rollout metric including cached input. Detect missing, decreasing, malformed and stale usage. Maximum token overshoot remains unknown until supported by actual observation and in-flight limits; never substitute a native display metric with different semantics.
- Outcomes distinguish held/unsupported admission, running, stopping, stopped and uncertain termination. Goal pause or RPC acknowledgment alone is not process-stop proof. Persist an exhaustion fence before automatic resumption can occur.
- Checkpoint preparation consumes an explicit reserve within original caps. Force termination when grace expires even if no new checkpoint is available. Retain last verified artifacts and unknown final usage conservatively.
- Strict elapsed-time claims require qualified suspend/resume behavior and an absolute deadline check before restart admission. Where the host cannot support the requested guarantee, reject rather than reset time or downgrade silently.
- Explicit operator renewal retains prior consumption and authorization history. Defaults changes, fresh context and a restarted service do not renew work.

## Testing Decisions

Primary seam: public lifecycle launch/status/stop behavior with disposable dedicated execution and independent OS evidence. Preserve existing ledger and lifecycle fixture tests as regression coverage; add host-adapter fixtures where deterministic failure injection is required. Test observable contracts rather than mirroring internal methods.

- Admission refuses missing/inconsistent controls and uncontained/shared execution before task effects; default legacy behavior is not silently enrolled.
- A real isolated Codex executor, active tool and child are demonstrably in the declared boundary, and an unrelated sentinel survives stopping it.
- Deadline and accounting-loss/controller-death cases terminate owned execution with stated detection/grace timing and process/cgroup readback. Native transport failure cannot prevent independent termination.
- Actual token exhaustion records accounting semantics, publication/detection delay, final unknown usage and observed overshoot. Injected telemetry tests are explicitly labeled and cannot substitute for native proof.
- Concurrent admission, preflight, retries, reviewers and successors are charged once; restart and refresh preserve the original deadline and allowance.
- Suspend/resume and unsupported-host cases enforce or refuse the claimed time guarantee; checkpoint failure cannot postpone the stop.
- Lost create/stop responses reconcile exact invocation identity without targeting unrelated or replacement work.
- Explicit renewal preserves historical spend and the original deadline record, while recording newly authorized bounds separately.

Host feasibility experiments and38 existing fixture tests are supporting prior art. They do not establish actual native containment or a finite token overshoot bound. Each implementing slice must leave its own bounded current evidence.

## Out of Scope

Creating this specification does not change #270's research-only scope or close it.
