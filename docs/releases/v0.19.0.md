# v0.19.0 — Controller maintenance and acceptance safeguards

Host operators can prepare a private, bounded graceful controller handover while
all unlatched campaigns are inactive. The permit binds the controller process
and generation, policy and allocation authority; graceful replacement preserves
all existing latches, accounting boundaries and deadlines. Aborted preparation
expires; changed or expired handovers fail closed. There is no resource renewal,
goal restoration or shared native daemon restart.

First-stop diagnostics retain typed native method/cause, observation duration,
clock qualification, controller identity and the budget snapshot before later
polls overwrite ordinary status. Existing legacy latches are explicitly labeled
as first retained observations rather than reconstructed historical faults.

A reusable opt-in real-agent launcher rejects blocked permissions before model
dispatch, verifies the installed MCP and fresh watcher, then checks one fixed
allowance through checkpoint/pause/operator reply and owned cleanup. Its fixture
tests use no external provider. Existing paid acceptance is not repeated.

CI adds a pinned undefined-name gate and retains both required Python job names.
Only ordinary added/modified evidence Markdown or parseable JSON can use the
short lane; unknown/source/policy/workflow/manifest/rename/deletion changes and
weekly scheduled runs execute full release gates. The installed skill is now a
short router; detailed workflows and historical plan evidence are preserved.

Compatibility: receipt/ledger `first_stop` fields and private maintenance permits
are additive. No allocation, wake-record or native caller authority is reset.
