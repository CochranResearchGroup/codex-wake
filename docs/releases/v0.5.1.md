# v0.5.1

Date: 2026-09-04

## Summary

`v0.5.1` is a maintenance release that makes delayed wake delivery safer when
another writer is active, when prompts cross repository boundaries, and when
persisted service commands or enrolled repositories move over time.

## Changes

- App-server dispatch now fails visibly on active-writer contention by default
  and never calls `turn/start` while the target is active.
- Added `--retry-active-writer` for callers that explicitly want the existing
  bounded three-attempt backoff policy.
- Canonical tmux, app-server, and OpenClaw prompts now include the owning
  absolute `WAKE_TRIGGER_ROOT` alongside `WAKE_TRIGGER_ID`.
- The Codex hook resolves explicit owning roots across active and archived
  records and returns do-not-resume context for terminal archived wakes.
- Removed the redundant project-scoped hook configuration; the user hook is
  the single installed hook source on the release workstation.
- Persisted Node-backed service commands resolve through stable executable
  paths instead of version-manager shims.
- User service path conditions prevent restart storms after enrolled
  repositories are removed.
- Bumped OpenClaw plugin package and manifest metadata to `0.5.1`.

## Compatibility

Wake-record schema version remains `1`. Existing records remain readable.
Records without `retry_active_writer` use the safer fail-closed default. Older
id-only canonical prompts retain cwd-based hook lookup; new prompts carry an
absolute owning root.
