# v0.6.0

Date: 2026-09-27

## Summary

`v0.6.0` turns Codex Wake's event-source and delivery layers into a broader,
restart-correct product surface. It adds built-in filesystem, process-exit,
user-systemd, GitHub CI, managed webhook, and generic HTTP/JSON completion
sources while making tmux delivery follow the exact Codex session instead of a
stale pane identifier.

## Changes

- Added a crash-safe signal journal, source registry, deterministic
  reconciliation, bounded dispatch attempts, and lifecycle/support commands.
- Added productized filesystem, process-exit, current-user systemd, GitHub CI,
  signed webhook, and fixed-origin HTTP/JSON completion sources.
- Added managed GitHub webhook ownership, rotation, health, cleanup, and a
  retained dispatch-disabled listener/poller deployment path.
- Added same-user GitHub CLI credential resolution without persisting token
  values in wake configuration.
- Corrected app-server command readiness so the user supervisor owns and
  reports the exact stable Codex executable used for dispatch.
- Bound tmux delivery to the durable Codex thread and client-process identity,
  including unique pane relocation and exact-thread app-server fallback.
- Expanded installed-wheel smoke coverage across source lifecycle, readiness,
  upgrade, support-export, and no-dispatch supervisor behavior.

## Compatibility

Wake-record schema version remains `1`. Signal records use their existing
schema version `2`; the new source families and tmux identity fields are
additive. Existing timer and file wakes remain readable.

Tmux wake creation now requires a current Codex thread identifier and resolves
the actual thread-owned pane. This intentionally rejects ambiguous or legacy
pane-only creation contexts instead of risking delivery to the wrong session.
