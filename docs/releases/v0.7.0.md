# v0.7.0

Codex Wake adds explicitly enrolled local agent mailboxes and notification
delivery through existing stock-Codex Byobu/tmux clients. A sender can register
a durable reply arm, end its turn, and receive the correlated reply notification.

The release includes exact-thread discovery and capability validation, mailbox
receipts and deduplication, bounded native notification workers, guarded client
generation/composer checks, backup/retention/recovery commands and installed
compatibility qualification. Notification delivery holds busy, disconnected or
draft-bearing clients; it never automatically launches a disconnected thread.
Worker restart reloads durable pending messages and reply arms. Unknown effects
require reconciliation rather than automatic replay.

See [A2A setup and service](../a2a-notifications.md) for the public installation,
enrollment, binding, sender delegation, explicit bounded user-service ownership
and actual actor exchange. The shipped service stops after its bounded window
or effect budget; it does not automatically restart.

Wake-record schema1 and signal-record schema2 remain supported. A2A mailbox
schema2 requires explicit migration, and older schema1 readers refuse it.
v0.6.0 has no A2A CLI; retain the store across a CLI downgrade. The separately
versioned OpenClaw plugin remains0.6.0 and its installed runtime is not changed.

Plan0119 verification0115,0117 and0118 preserve actual stock-Codex round-trip,
cancellation, clean reconnect and owned-worker restart evidence. Normal public
installation, multiroot, rollback and30-minute soak receipts are separate gates
and must be recorded before declaring the full plan complete.
