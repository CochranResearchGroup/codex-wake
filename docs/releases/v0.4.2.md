# v0.4.2

Date: 2026-05-19

## Summary

Releases PID-reuse hardening for `process_done` wake predicates.

## Included

- `codex-wake pid <pid> -- <prompt>` now records Linux process identity when available.
- Process identity includes `/proc/<pid>/stat` start time and `/proc/sys/kernel/random/boot_id`.
- `codex-waked` now fires `process_done` when a live PID no longer matches the registered process identity.
- Existing PID-only records and platforms without process identity data continue to use PID-liveness fallback.
- README documents the stronger Linux behavior and fallback limit.
- P19 validation evidence for source tests, source CLI smoke, and installed-wheel CLI smoke.

## Verified

- Source tests and compileall.
- Local package build from a temporary build venv.
- Installed-wheel smoke for `codex-wake`, `codex-waked`, and `codex-wake-hook`.
- Installed-wheel live PID smoke confirming identity capture, pending state while the process lives, and `pending -> firing` after exit.
- Clean public tag install and command smoke.
- GitHub Actions CI on the public upstream.

## Known Limits

- PID identity capture is best-effort and falls back to liveness when `/proc` identity data is unavailable.
- CI does not force a real PID reuse event; unit tests cover identity mismatch directly.
- This release does not change wake record schema version because the new predicate fields are optional and backward-compatible.
